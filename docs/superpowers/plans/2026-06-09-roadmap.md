# EmojiSurvivors — Feature Roadmap (Content · Juice · Meta · QoL/Modes)

> Date: 2026-06-09 · Status: **planned, pre-implementation**
> Built on the shipped game (live at https://dev.jdayers.com/survivors/, SW v11).
> Three areas were planned by codebase-grounded agents; a fourth (QoL/Modes/Modifiers)
> was added from later requests. Items reference real files/functions/data shapes.

## Cross-cutting rules (apply to every item)

- **Architecture holds:** sim stays DOM-free (Engine/Systems/World/Content); new feedback
  is driven by sim `events[]` routed in `Main.handleEvents` → Sfx/Particles/Fx; content is
  data-only defs in `Source/Content/*`. Vanilla ESM, buildless, PascalCase.
- **Every deploy:** bump `ServiceWorker.js` `CACHE`; add ANY new `Source/*` file to
  `SHELL_FIRST_PARTY`; add new `Tests/*.Test.js` to `Tests/RunAll.js`; Prettier; `npm test`
  green; rsync (README/CLAUDE/docs/Tests excluded); curl-verify; re-run `BalanceProbe`.
- **Save:** additive fields + `migrate()` forward-fill, bumping `SAVE_VERSION` each time.
  `migrate()` already coerces to the current schema, so versions can climb incrementally
  (v2, v3, …) safely — no need to land everything atomically.
- **Determinism:** new sim inputs (manual-aim vector, fast-forward) flow through
  `state.input` / fixed-step accumulation so `SimProbe` stays reproducible.

## Resolved decisions (from agent risks / open questions)

- New normal enemy renamed **`specter`** (not `wraith`) — `wraith` is the 5-min boss id.
- Lucky Charm passive emoji → **🃏** (🍀 already used by the Luck power-grid row).
- **Banish** is a separate free resource (1/run) — not shared with reroll. Power-grid
  extension (`stat:'banishes'`) is a later option.
- Elite spawning moves from a single `ELITE_ID` to **`ELITE_IDS=['ogre','lich']`** with
  `state.spawn.eliteTimers = {ogre, lich}` (update Spawner.Test).
- `restart()` in Main must forward `state.hardMode` (and the chosen modifiers) so a retry
  preserves the run config.
- Frost Lance "chain" spawns children in **CombatSystem** at the impact point; the proj
  pool factory + `spawnProj` must initialize `chainCount`/`chainRange` (like `hitIds`).
- Most-Collected records = cumulative per-id counts across runs (rewards breadth).

## Phase 3 — Modes & Modifiers (the big new system) · 1–2 deploys

| Item | Effort | Risk | Files |
|---|---|---|---|
| **Hard Mode toggle** (Config checkbox, run flag, ×stats/×rewards) | M | med | ConfigScreen.js, State.js, Spawner.js, Main.js, Hud.js |
| **Modifiers engine** (data defs + per-run resolve + system hooks) | L | med | NEW Content/Modifiers.js, State.js, Leveling.js, StatsModel.js, Spawner.js, PickupSystem.js, Weapons.js |
| **Endless mode** (no boss-end, weapons past cap, escalating) | M | med | Modifiers.js, Spawner.js, Leveling.js, Weapons.js (scaleWeapon clamp) |
| **Modifiers screen + unlock-by-play + persistence** | L | med | NEW UI/ModifiersScreen.js, Meta.js, Save.js, MenuScreen/ConfigScreen, Main.js |
| **Manual aim mode** (cursor desktop / aim-dir mobile) | M | med | Input.js, WeaponSystem.js, Main.js, SettingsScreen.js, Save.js |

**Modifiers engine.** `Content/Modifiers.js` exports data-driven mutators applied to a
per-run `state.modifiers` config (resolved at run start from the player's selection):

- **Rule mutators:** `maxWeapons` (3–8; Leveling reads `state.modifiers.maxWeapons` instead
  of the `WEAPON_SLOTS` const), `maxPassives`, `xpMul` (PickupSystem gem XP ×), `monsterMul`
  (Spawner cap ×), `monsterSpeed` (spawnEnemy speed ×), `coinMul`, `startLevel`, `extraRevives`,
  `weaponLevelCap` (scaleWeapon/Leveling read per-run cap; ∞ for endless).
- **Modes:** `endless` (Spawner skips the deadline boss or spawns recurring bosses; difficulty
  keeps ramping; run ends only on death), `bossRush`, `oneWeapon` (lock the new-weapon pool).

**Unlock-by-play:** modifiers gated behind `save.unlockedModifiers` (migrate-filled). New
runs grant progress (e.g. first win → Hard; 5 wins → Endless; play counters in Meta).
`ModifiersScreen` lists them (locked show the unlock condition), toggles/sets values, passes
the active set into `startRun`. `restart()` preserves it.

**Manual aim:** `settings.aimMode:'auto'|'manual'`. `Input.getAim(camera,player)` →
normalized aim (cursor on desktop, last-move/secondary-touch on mobile); Main writes
`state.input.aim`; in manual mode `WeaponSystem` directional behaviors (aimed/spread/whip/
nova) use `state.input.aim` instead of nearest/facing. Aim is an input → probe-settable →
deterministic.

> **More modifier ideas** (pick a launch subset, rest are append-only later): glass-cannon
> (×dmg, ×fragility), Curse (harder → ×rewards, à la VS), magnet-always-max, randomizer
> (random pick each level), no-evolutions / forced-evolutions, double-XP-half-coins, tiny/big
> enemies (cosmetic), hardcore (no revives), time-attack (kill boss fast for bonus),
> pacifist-window bonuses, mirror (two starting weapons).

## Open questions for the human

1. **Modifiers unlock currency:** unlock by *wins/play count* (suggested) or *spend coins*?
2. **Endless escalation:** uncapped ramp (eventually unsurvivable) or plateau + periodic
   boss waves for score? Endless needs a *score* to make "forever" meaningful.
3. **Hard Mode reward:** ×coins/×XP only, or also unlock-gated content/achievements?
4. **Achievements:** purely cosmetic records, or grant a small coin bonus on first unlock?
5. **Launch modifier set:** which of the brainstorm list ship first vs. deferred?
